# Overlay Performance and UI Fixes

## 本轮针对的问题

用户反馈：

- 搜索结果显示太挤、太窄。
- 搜索完成后切换菜单会卡一段时间。
- 切换菜单时会短暂白屏。
- 悬浮窗整体背景还不够半透明。

## 修改文件

`android/app/src/main/kotlin/com/yl/aigg/ai_gg666/OverlayService.kt`

## 已完成修复

### 1. 面板切换减少白屏

原逻辑：

1. 先 remove 当前面板。
2. 再 add 新面板。

这样在面板复杂或搜索结果多时，可能出现短暂白屏。

新逻辑：

1. 先添加新面板。
2. 新面板淡入。
3. 32ms 后移除旧面板。

已改方法：

- `showFullscreenPanel(...)`
- `showFocusableFullscreenPanel(...)`

### 2. 全屏背景半透明增强

全屏菜单和子面板外壳已调整：

- 遮罩透明度降低，能看到后方游戏画面。
- 主 shell 使用 `Color.argb(226, 248, 242, 233)`。
- shell 自身 alpha 设置为 `0.96f`。
- 子面板内容区使用原 `bgColor`，并加入 alpha，避免文字对比度失效。

### 3. 搜索结果显示更宽松

原结果项：

- 单行横向布局。
- 机器码、地址和值挤在一行。
- 文字偏小。
- 按钮只有“改 / 冻”。

新结果项：

- 改为纵向卡片。
- 第一行显示序号、地址、值。
- 第二行单独显示机器码。
- 操作按钮改为“修改 / 冻结”。
- 卡片边距、圆角、字体层级更清晰。

### 4. 搜索结果渲染数量优化

原来最多渲染 300 条结果，容易造成大量 View 创建，从而导致切换菜单卡顿。

新限制：

- 横屏最多显示 120 条。
- 竖屏最多显示 80 条。

并增加提示：

`显示前 N / 共 M 条 · 点击卡片可修改，勾选后可批量操作`

这样搜索结果过多时不会一次性创建过多 View。

## 后续建议

1. 如果还卡，继续把结果列表改为 RecyclerView，而不是 ScrollView + LinearLayout。
2. 搜索结果超过 80 / 120 时加入“加载更多”。
3. 子面板内部控件继续统一成卡片和胶囊按钮。
4. 给悬浮球增加状态点，显示当前是否已附加进程。
